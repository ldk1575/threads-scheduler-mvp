# 실행 치트시트

글 한 편 올리는 데 필요한 명령 전부. 매번 이 문서만 보면 된다.

> ⚠️ **Windows PowerShell 5 는 `&&` 를 못 쓴다.** 한 줄씩 실행할 것.
> 한 줄로 이으려 하지 마라 — 터미널 종류마다 다르게 동작한다.

---

## 매번 쓰는 것 — 4단계

### 0. 폴더로 이동

```powershell
cd "D:\2026년\threads-publish-mvp"
```

### 1. 연결 확인

```powershell
npm run cli -- connect
```

```
연결됨 — @<계정> (id 2826...)
쿼터 — 0 / 250 사용, 남음 250
→ 발행 가능
```

**여기서 막히면 그다음을 하지 마라.** 토큰이 죽었거나 권한이 없는 것이다.

### 2. 글 만들기 — **아직 안 올라간다**

```powershell
npm run cli -- generate "여기에 주제"
```

일어나는 일:

| 순서 | 무엇 |
|---|---|
| 1 | 훅 3종을 **코드가 골라 지정**. 최근 쓴 훅은 피한다 |
| 2 | LLM 호출 (primary 죽으면 secondary 로 폴백) |
| 3 | **검증 게이트** — 100자 초과·훅 중복·판매어·실제 URL 이면 거절 |
| 4 | 거절되면 **사유를 모델에 돌려주고 한 번 더** 요청 |
| 5 | **안전 필터 2단** — 키워드 → AI 적합성 판정 |
| 6 | 통과한 것만 `.data/drafts.json` 에 저장 |

화면에 글 3개가 뜬다. **눈으로 읽고 고른다.**

### 3. 올릴 글 확인 — **아직 안 올라간다**

```powershell
npm run cli -- publish 1 --dry
```

`1` 을 `2` / `3` 으로 바꾸면 다른 글.

### 4. 실제 발행 — **여기서 진짜 올라간다**

```powershell
npm run cli -- publish 1
```

```
쿼터 남음 250 → 발행합니다...
✓ 올라갔습니다
  permalink: https://www.threads.net/@<계정>/post/...
```

**되돌리려면 스레드 앱에서 직접 지워야 한다.**

`.data/drafts.json` 의 `text` 를 직접 고친 뒤 `publish` 하면 된다. 100자만 넘지 않으면 된다.

```powershell
notepad "D:\2026년\threads-publish-mvp\.data\drafts.json"
```

한 줄로 바꾸려면:

```powershell
node -e "const f='.data/drafts.json';const d=JSON.parse(require('fs').readFileSync(f,'utf8'));d.posts[0].text='바꿀 내용';d.posts[0].char_count=d.posts[0].text.length;require('fs').writeFileSync(f,JSON.stringify(d,null,2));console.log('바꿈 —',d.posts[0].char_count,'자')"
```

## 문제가 났을 때

### 무엇을 받았는지 보기

```powershell
$env:LLM_DEBUG=1
```

모델이 준 원문을 그대로 출력한다. 끌 때:

```powershell
$env:LLM_DEBUG=""
```

### 자주 나는 오류

| 증상 | 원인 · 대처 |
|---|---|
| `'&&' 토큰은 올바른 문 구분 기호가 아닙니다` | PowerShell 5. **한 줄씩** 실행 |
| `Object with ID '<이름>' does not exist` | 사용자명을 넣었다. `THREADS_USER_ID` 를 **비워 두면** 코드가 푼다 |
| `Session has expired` / `code 190` | 토큰 만료(60일). 재발급 필요 |
| `requires threads_content_publish` | 발행 권한 없는 토큰 |
| `E-LLM-422: 응답에 JSON 이 없다` | 에러에 **받은 내용**이 같이 나온다. 그걸 보고 판단 |
| `E-LLM-401: ... API_KEY 가 없다` | `.env` 에 키가 없거나 `LLM_PRIMARY` 가 그 백엔드를 가리킴 |
| `Media ID does not exist` | 2단계 발행 경합. **다시 돌리면 된다** |
| `쿼터가 없다 — 발행하지 않는다` | 24시간 250건 소진. 창이 지나면 풀린다 |

## 절대 하지 말 것

- **`.env` 를 커밋하지 마라.** `.gitignore` 에 걸려 있지만 `-f` 로 강제하지 마라
- **`service_role` / `secret` 키를 브라우저로 내려보내지 마라.** RLS 를 우회한다
- **`publish` 를 확인 없이 돌리지 마라.** 되돌릴 수 없다

## 사람이 봐야 하는 자리

코드가 잡는 것과 못 잡는 것이 다르다.

**게이트가 잡는다 (형식)**
100자 초과 · 훅/구조 중복 · 직접 판매어 · 실제 URL · CTA 누락 · 반복 문구

**사람이 봐야 한다 (진위)**
- **겪지 않은 일을 겪은 것처럼 쓰지 않았는지**
- **지어낸 숫자가 없는지** ("2분 만에", "87%가")
- 내 계정 톤에 맞는지

실제로 모델이 *"내 API 키가 다 털리고 있더라고"* 라고 쓴 적이 있는데 **안 털렸다.**
그래서 `generate` 와 `publish` 가 나뉘어 있다. 그 사이가 사람이 보는 자리다.
