# 열린 항목

정했지만 아직 코드에 없는 것, 확인이 필요한 것을 여기 모은다.

**왜 이 파일이 생겼나** — "답글을 2시간 안에 분산해서 달자"고 정했는데 어디에도
안 적혀 있었다. `docs/이어서-*.md` 는 그날 한 일을 적는 문서라 *안 한 일*이 낄
자리가 없었다. 그래서 첫 댓글이 본문과 같은 분에 나가는 걸 실제로 올리고 나서야
알았다. 결정은 코드보다 오래 살아야 한다.

작업이 끝나면 그 항목을 지우고 커밋 해시를 `docs/이어서-*.md` 에 남긴다.

---

## 1. 남의 글에 다는 답글 분산 (Phase 2)

**상태** — 미구현. 답글 자동응대 기능 자체가 아직 없다.

남의 글에 답글을 연달아 달면 스팸으로 읽힌다. **2시간 창 안에 흩어서** 단다.
간격을 일정하게 두면 그것도 티가 나므로 무작위로 벌린다.

관련 — `docs/회고.md` 에 "가장 아까웠던 건 답글 자동응대"로 남아 있다.
공식 API 에 `pending_replies` / `manage_reply` 가 있다.

내 글의 첫 댓글은 같은 규칙을 **수동으로** 지키고 있다 (`d55b083`).
`src/core/pending-replies.ts` 의 `MIN_REPLY_DELAY_MIN` / `MAX_REPLY_WINDOW_MIN`
가 그 값이다. Phase 2 를 만들 때 이 상수를 같이 쓰면 두 경로가 안 갈린다.

## 2. 첫 댓글 자동 예약

**상태** — 지금은 사람이 `npm run cli -- reply` 로 단다.

`processDueJobs()` 는 단일 패스라 외부 스케줄러가 깨워야 한다. 크론이나 워커가
생기면 `PendingReply` 를 그대로 예약 잡으로 옮긴다. 자료구조는 그 목적으로
만들어 뒀다.

**주의** — 예약이 생겨도 발행(POST)은 재시도하면 안 된다. `cfc0098` 참고.

## 3. 3D 아이콘 · "아지랑이" 효과 — 확인 필요

**상태** — 무엇인지 모른다. 실물을 봐야 한다.

스레드에서 **글씨 일부가 안 보이고 아지랑이처럼 움직이다가 마우스를 올리면
보이는** 게시물이 많이 보인다고 한다. 그게 어떻게 만들어진 건지 확인해야 한다.

지금 아는 것:

- 코드는 `media_type=TEXT` 컨테이너만 만든다 (`src/threads/client.ts`)
- Threads API 의 텍스트 본문은 순수 텍스트다. 서식·애니메이션·마우스오버가 없다
- 이모지가 입체로 보이는 건 기기 폰트다. 같은 글자가 다른 기기에선 평면이다

가능성 — (a) 앱의 가림막 기능, (b) 이미지/영상 게시물, (c) 우리가 모르는 새 기능.
**추측으로 만들지 말 것.** 게시물 링크를 받아서 열어 보고, 무엇으로 만든 건지
확인한 다음에 견적을 낸다. 이미지라면 이미지 첨부 경로와 호스팅이 따로 필요하다.

## 4. 첫 댓글 조언이 배치마다 엇갈린다

**상태** — 미해결.

클렌징 순서 조언이 생성할 때마다 달라진다.

- 어느 배치 — `물 묻혀서 하얗게 변할 때 최소 30초는 문질러줘야`
- 다른 배치 — `물기 완전히 닦고 발라야 해`
- 또 다른 배치 — `딱 30초만 해야 해` (위와 반대 방향)

단계가 달라서 셋 다 틀린 말은 아니다. 다만 같은 계정 글이 나란히 붙으면
읽는 사람은 엇갈린다고 느낀다. 순서를 프롬프트에 고정할지, 아니면 사람이
발행 전에 고를지 정해야 한다.
