### ① 왜 하한을 걸었나

스레드 상한은 500자인데 우리 게이트는 100자였다. 올라간 글이 전부
"훅 + 한 문장 + 질문"이었고 고백경험담형·스토리텔링형이 들어갈 자리가 없었다.

**상한만 올리면 소용없다.** 모델은 짧은 쪽이 안전하니 계속 짧게 쓴다.
그래서 `MIN_POST_CHARS = 200` 을 같이 걸었다. **하한이 진짜 장치다.**

### ② 첫 댓글이 하나도 안 달렸던 이유

버그가 아니라 배선이 없었다.

| 어디 | 첫 댓글 코드 |
|---|---|
| `client.replyTo()` | 있었음 |
| `worker/publish-due.ts` | 있었음 |
| **`cli/main.ts`** | **없었음** ← 사람이 실제로 쓰는 경로 |
| `generate` 출력 스키마 | 필드 자체가 없었음 |

둘 다 채웠다. **본문 발행 뒤 댓글이 실패해도 명령을 실패로 만들지 않는다** —
다시 돌리면 본문이 두 번 올라간다.

## 다음에 정할 것

### 측정을 흐리지 말 것

지금 대기 중인 변경이 넷이다. 한꺼번에 켜면 **뭐가 효과였는지 못 가린다.**

```
1주차   ①②③ 켜고 텍스트만        → 중앙 조회수(기준선 153)와 비교
2주차   같은 조건에서 미디어 추가   → 미디어 효과만 분리됨
```

**기준선**: 12개 기준 중앙 조회수 **153**, 최고 배수 **3배**, 평균 반응 **1**, 팔로워 60.
(확장프로그램 스크린샷이 유일한 기록이다. 글을 지우면 다시 못 본다.)

미디어가 확실히 세면 **미디어 발행을 API 로 붙이는 것**이 다음 우선순위가 된다.
지금은 텍스트 전용으로 잘라 둔 상태다.

## 게이트가 못 잡는 것

첫 댓글 프롬프트에 "실패했던 순간, 해보고 알게 된 디테일"을 요구했더니
**모델이 없는 경험을 지어냈다.**

> "엄마한테 넵, 알겠습니다! 했다가 엄마가 서운해하셨음"
> "친구랑 엄청 크게 싸운 적 있음"

셋 다 겪지 않은 일이다. **구체성을 요구한 대가다.** 게이트는 형식만 보니 못 잡는다.

그래서 `generate` 와 `publish` 가 나뉘어 있다. **그 사이가 사람이 보는 자리다.**

바꿀지 말지는 다음 반응을 보고 정한다.
프롬프트를 "일반론으로 쓰라"로 바꾸면 안전하지만 글이 밋밋해진다.
